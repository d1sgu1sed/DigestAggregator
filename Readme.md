# Агрегатор новостей с функцией дайджеста

## Задача:
Необходимо написать сервис, который собирает новости из открытых источников (RSS/API), сохраняет их в БД и позволяет получить краткую сводку за указанный период.

### Требования:
 1. Сбор: Реализовать парсер для 2-х источников новостей (например, RSS ленты). Сбор должен быть автоматическим (планировщик) или по команде.
 2. Хранение: БД (любая). Предусмотреть защиту от дублей (одна новость не должна сохраняться дважды).
 3. Отчетность: Реализовать метод/команду получения сводки.
 + Входные параметры: период (день/неделя).
 + Выход: Список основных событий или краткий текстовый файл.
 4. Будет плюсом:
 + Использование Docker.
 + Наличие юнит-тестов.
 + Использование LLM для генерации красивого описания новостей.
 + Обработка ошибок сети (таймауты, недоступность сайтов).
 + Использование Google Alerts.

### Стек разработки:

| Задача | Инструмент |
|--------|------------|
|HTTP-запросы|`httpx`|
|Парсинг RSS|`feedparser`|
|События при сбоях в сети|`tenacity`|
|БД|`PostgreSQL + SQLAlchemy`|
|Интерфейс|`FastAPI + Typer`|
|Миграции|`Alembic`|
|Планировщик|`APScheduler`|
|Тесты|`pytest`|
|Контейнеры|`Docker + docker-compose`|

## Возможности

+ Сбор из RSS/Atom-лент, Google Alerts и API - по расписанию (APScheduler) или по команде.
+ Источники по умолчанию: Хабр и Коммерсантъ; свои ленты добавляются через API или CLI.
+ Защита от дублей на уровне БД: по нормализованному URL и по guid записи внутри источника.
+ Сводка за день или неделю - списком по источникам или текстовым файлом.
+ Описание отдельной новости и дайджест главных событий за день/неделю при помощи нейросети.
+ Обработка ошибок сети: таймауты, повторы при временных сбоях, недоступный источник не прерывает работу.

## Быстрый старт

Нужны Python 3.11+ (проверено на 3.14), Docker и Ollama (для нейросети)

```bash
# 1. Окружение и зависимости
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Настройки: скопируйте шаблон и укажите свои логин/пароль БД
cp .env.example .env

# 3. PostgreSQL в Docker (db — рабочая БД, db_test — для тестов)
docker compose up -d

# 4. Схема БД
alembic upgrade head

# 5. Первый сбор новостей
python -m app collect
```

Запуск API (вместе с ним запускается планировщик сбора):

```bash
uvicorn app.api.main:app --reload
```

Документация API (Swagger) — http://127.0.0.1:8000/docs

### Нейросеть

```bash
ollama pull gemma3:4b              # точнее перевод и русский язык
ollama pull qwen3:4b-instruct      # быстрее, но чаще ошибается
```

## Командная строка

Все команды: `python -m app <команда>`, справка по любой — `--help`.

| Команда | Что делает |
|---|---|
| `collect` | Собрать новости со всех активных источников |
| `scheduler [--interval N]` | Собирать каждые N минут |
| `digest [-p day\|week] [--per-source 10] [-o файл]` | Сводка без нейросети: в терминал или в текстовый файл |
| `sources list` | Источники: число новостей, последний сбор, ошибка |
| `sources add НАЗВАНИЕ URL [-t rss\|google_alerts] [--no-verify]` | Добавить ленту |
| `sources remove ID [-y]` | Удалить источник вместе с его новостями |
| `llm describe NEWS_ID [-m модель] [-r]` | Описание новости нейросетью (`-r` — сгенерировать заново) |
| `llm digest [-p day\|week] [-m модель] [-o файл]` | Дайджест главных событий от нейросети |

`-v` перед командой включает подробный лог: `python -m app -v llm digest -p week`.

Примеры:

```bash
python -m app digest -p week -o week.txt
python -m app sources add "Новая газета Европа" https://novayagazeta.eu/feed/rss
python -m app llm digest -p day -m qwen3:4b-instruct
```

> Не запускайте `scheduler` одновременно с API, у которого включён планировщик (`SCHEDULER_ENABLED=true`), — сбор будет идти дважды.

## HTTP API

| Метод и путь | Что делает |
|---|---|
| `GET /health` | Состояние БД и планировщика |
| `GET /sources` | Источники и их статус |
| `POST /sources?verify=true` | Добавить ленту: `{"name": "...", "url": "...", "type": "rss"}` |
| `DELETE /sources/{id}` | Удалить источник вместе с новостями |
| `POST /collect` | Собрать новости сейчас (`409`, если сбор уже идёт) |
| `GET /digest?period=day&per_source=10&format=json` | Сводка |
| `POST /news/{id}/describe?model=...&regenerate=false` | Описание новости нейросетью (id - из `GET /digest`) |
| `POST /digest/llm?period=week&model=...` | Запустить генерацию дайджеста нейросетью (фоновая задача, ответ `202`) |
| `GET /digest/llm/{id}?format=json` | Статус и результат (`pending` -> `running` -> `done`/`failed`) |
| `GET /digest/llm?limit=10` | Последние дайджесты нейросети |

```bash
curl "http://127.0.0.1:8000/digest?period=week&format=text"
curl -X POST "http://127.0.0.1:8000/digest/llm?period=day"
curl "http://127.0.0.1:8000/digest/llm/5?format=text"
```

Дайджест нейросети за день готовится около минуты, за неделю - несколько минут (на GTX 1650, 4 ГБ).

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | - | Рабочая БД |
| `POSTGRES_HOST`, `POSTGRES_PORT` | `127.0.0.1`, `5432` | Адрес БД |
| `TEST_POSTGRES_*` | - / `127.0.0.1`, `5433` | Тестовая БД |
| `GOOGLE_ALERTS_FEED_URL` | не задан | RSS-лента Google Alerts - добавится как источник |
| `SCHEDULER_ENABLED` | `true` | Планировщик внутри API |
| `COLLECT_INTERVAL_MINUTES` | `30` | Интервал сбора |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Адрес Ollama |
| `LLM_MODEL` | `gemma3:4b` | Модель по умолчанию (`gemma3:4b` или `qwen3:4b-instruct`) |
| `LLM_TIMEOUT_SECONDS` | `120` | Таймаут ответа модели |
| `LLM_DIGEST_PER_SOURCE_PER_DAY` | `10` | Сколько новостей источника за день попадает в дайджест нейросети |

Используйте `127.0.0.1`, а не `localhost`, т.к. на некоторых системах `localhost` указывает на IPv6, и подключение к Docker зависает.

## Тесты

```bash
docker compose up -d db_test
pytest
```

Тесты сами накатывают миграции на тестовую БД и не обращаются к сети. Если тестовая БД не запущена, тесты с БД пропускаются.
